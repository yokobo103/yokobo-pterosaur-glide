# 測定記録 — 2026-09-16

飛距離をスコアにできるか、工夫の余地があるかを、実装前に測った記録。
既存 `20260912_Pterosaur_Wind_PoC/scripts/wind_model.py`（滑空・旋回・ガウシアンの上昇柱）を
km規模・複数サーマルへ広げ、自動操縦で飛ばして比較した。空力シミュレーションではない。

## 1. 制限時間を置くと工夫が消える

| | 制限時間20分 | 制限なし |
|---|---|---|
| 上昇風を使わず直進 | 3.55km | 2.97km |
| いちばん良い乗り方 | 3.99km | 11.06km |
| 差 | 12% | 3.7倍 |

1本の上昇風で高度を稼ぎ切るのに数百秒かかる。時計を置くと旋回した分だけ純粋に損になり、
「乗らない方が速い」が正解になる。

## 2. 飛距離だけ・無制限だと走行が終わらない

場を無限（チャンク生成）にして飛ばすと **281km / シム内7時間**。上手いほど落ちない。
→ 時計ではなく**日没**（上昇風が夕方に向かって弱る）で終わらせる。

## 3. 工夫の余地は5倍。下手に乗ると使わないより悪い

日没モデル・72通りの戦略・8シードでの平均。

| 乗り方 | 飛距離 |
|---|---|
| いちばんまずい | 2.22km |
| 使わず直進 | 2.97km |
| 真ん中 | 4.27km |
| いちばん良い | 11.06km |

**2.22km < 2.97km** が重要。「とりあえず全部乗る」が正解にならない。

## 4. 効くつまみは2本、効かないつまみが2本

| 判断 | 飛距離の振れ幅 |
|---|---|
| どれに乗り、どれを見送るか | 4.39km |
| どれくらいの速さで飛ぶか | 2.27km |
| どこまで高度を上げるか | 0.68km |
| どれだけ寄り道するか | 0.45km |

弱いのに片端から乗る(3.44km)のも、強いのだけ待ちすぎる(3.53km)のも同程度に悪く、真ん中に山がある。
**効くのは「見送る勇気」**であって、当初想定した「旋回への投資」ではなかった。

## 5. 速度操作は上限を伸ばさない → 左右だけにする

| 操作 | 最悪 | 中央 | 最良 |
|---|---|---|---|
| 左右＋速度（2軸） | 2.22km | 4.27km | 11.06km |
| 左右のみ（速度自動） | 3.53km | 6.09km | 11.06km |

天井が同じ。速度を足しても上手い人の上限は伸びず、下手な人がより下手になるだけ。

## 6. 芯を外したときの損（旋回の腕前の感度）

上昇風の半径70m・旋回半径13mでの試算。

| 芯からのずれ | 300m上がるのに |
|---|---|
| 0m | 3.3分 |
| 40m | 4.5分 |
| 80m | 16.6分 |
| 100m | 上がれない |

→ 上昇率が分からないと左右の操作が運になる。音（バリオメーター）が必須。

## 7. 地形ごとに最適が変わる

地形に合わせてつまみを変えると、最良の固定戦略より平均+21%（最大+49%）。
腕前の8割は一度覚えたつまみ、2割が毎回の読み。

## 実装後に分かったこと

- **上昇風の外の沈下が要る。** 無いと素通りするだけで高度が増え、直進でも7.3km出て「見送る」に代償が無くなる（`TUNE.ambient`）
- **近すぎる粒は消さないと画面を塞ぐ。** 旋回中、縦持ちで特に致命的だった（頂点シェーダで距離フェード）
- **点のサイズは距離の逆数だけで決めると遠景が見えない。** 遠くの柱は「見つける対象」なので最低2pxを持たせた

## 左右の符号を2か所間違えていた（2026-09-16 遊んでの指摘から）

所長の指摘:「右が上がったら左に曲がるんじゃない？」「旋回後にカメラがリセットされない」「先端がこちら側を向く」

**原因1: 機体の向きが左右反転していた。**
`glider.rotation.y = -head` としていたが、描画側の座標を反転していなかったため、
機首が進行方向と反対側を向いていた。出発時は head=0 なので正しく見え、
**曲がった角度の2倍だけ機首がずれていく**。一周すれば機首はこちらを向く。
所長が見たのはこれ。

**原因2: three.jsは右手系で +X は画面の左に出る。**
シミュレーション側の x(右が正) をそのまま渡していたので、
右を押すと画面では左へ曲がっていた。

**原因3(原因2を直したときに出た): X反転で三角形の巻き順が逆になり、地形が裏面になって消えた。**
背面カリングで地形が描かれず、下に敷いた水面が見えていた。

**検査が通っていた理由。**
タッチ検査は「右を押したら bank が正になるか」しか見ていなかった。
数字の符号は合っていて、画面がどちらに回るかを一度も確かめていなかった。
`tools/check-signs.mjs` を追加し、以下を見るようにした。

- 正面の目印が画面のどちらへ流れるか（右旋回なら左へ）
- 画面で右側にある翼が下がっているか
- 地平線の右側が上がっているか
- **機首の向きと進行方向のズレ**（0度でなければ機首が明後日を向く）

教訓: 向きや左右は、内部の数値の符号ではなく**画面のどちらへ動くか**で検査する。

## 画面酔い（2026-09-16 所長の試走）

直す前の版は、右バンクでカメラが**左へ**36度傾き、画面上の機体が88度倒れて見えていた（検査が左右の目印を取り違え、PASSと誤報していた）。
符号を直したうえで、カメラの型を3つ出して所長に選んでもらった。

| 型 | 地平線の傾き | 結果 |
|---|---|---|
| 水平キープ | 0度 | 酔わない |
| 見下ろし | 0度 | 酔わない |
| 少し傾く 0.3 | 14度 | 酔う（ただしクセは面白い） |
| 少し傾く 0.2 | 10度 | ギリギリ酔わない |
| **少し傾く 0.1** | **5度** | **快適 → 標準に採用** |

- 酔う/酔わないの境目は、この試走では地平線の傾き**10度前後**
- 傾かない型も選べるようにした（スタート画面、選択は次回も記憶）
- 画面が回る速さ（31度/秒＝旋回そのもの）はどの型でも同じで、今回は問題にならなかった

## 案C: 尾根の上昇風（2026-09-16 灰色の山で試作）

目的: 「暇」（静かな空気を滑るだけの時間が最長60〜74秒）を、地形を読む判断に変えられるか。
Astraに山を頼む前に、使える寸法を決めるための試作。

**山そのものが尾根沿いに飛べる形か**（tools/ridge-band.mjs。自動操縦を通さない測定）

| 山の形 | 高度を保てる区間 | 途切れずに続く最長 | 斜面からどこまで離れられるか |
|---|---|---|---|
| ノイズの山 550m | 60% | 1.1km | 80m |
| 進行方向につながった山脈 550m・裾700m・風11m/s | 76% | 2.5km | 75m |
| **同上・上昇が高くまで届く(ridgeH 240, 風下の下降を2.5m/sまで)** | **86%** | **2.5km** | **150m** |

→ ノイズの山より、**進行方向につながった山脈**が要る。鞍部で2.5kmごとに途切れる形は「上昇気流に乗り換えるか、次の尾根へ渡るか」の判断になる。

**自動操縦では確かめられなかった。** 36秒先まで直進を試す方式では、曲がる尾根の風上側に沿い続けられず、山ありだと飛距離が8.7km→2.8〜4.6kmに落ちた。暇な時間は最長60秒→1〜13秒に減ったが、尾根を使えたからではなく、風下の下降気流で揺さぶられて早く落ちたため。**面白いかは人が飛んで判断する段階。**

公開: `?world=ridge`（既定の山なし世界は変えていない）。風は左から。風上の斜面は明るく、急な斜面は岩の色。

### Astraに頼むなら（この試作から決まった条件）
- 形: 進行方向に長くつながった山脈。高さ約550m、裾の広さ約700m（最大傾斜およそ34度）、2.5kmおきに鞍部
- 受け渡し: 見た目のモデルではなく、飛行計算が読める形（高さマップ16bit PNG、または作り方の式）

## 尾根の風は不採用 → 丘の起伏と着地点の印（2026-09-17 所長の試走から）

所長: 「山風はよくわからんかった」。2回とも山の斜面に正面から激突して終わった（高度2m、斜面が目の前）。
→ 後ろから追うカメラでは「この先の山を越えられるか」が読めない。尾根の風は見えない上昇と斜面すれすれの怖さが重なる。
所長の提案: 起伏があるだけで「避けるか越えるか」の戦略になる。山へ向かうと地面との余裕は必然的に削られる。

**変えたこと**
- 既定の世界を「丘」に（`WORLDS.hills`、高さ最大220m、平地を残す）。尾根の風は既定で無効。`?world=flat` で起伏なし、`?world=ridge` は残す
- **このまままっすぐ滑空したら着く場所**をオレンジの輪と柱で地面に出す（上昇風は当てにしない計算）。旋回中は傾けるほど薄くする
  - 予測と実際の着地点のずれ: 60件で最大55m（tools/check-reach.mjs）
  - 最初は色がクリームで細く、土ぼこりに埋もれて見えなかった。オレンジ・太く・1km先で約55mの大きさにした
- 土ぼこりは画面に大きく映る粒ほど薄く（近い柱が空一面をふさいでいた）。手がかりの面積 3.7% → 2.8%（遠い柱は変わらず）

**自動操縦での比較（tools/tune-hills.mjs、8シード）**

| 条件 | 飛距離 | 静かな空気を滑るだけの最長 | 上り坂に激突して終わり |
|---|---|---|---|
| 起伏なし | 8.9km | 60秒 | 0/8 |
| 丘160m | 7.2km | 62秒 | 1/8 |
| **丘220m（採用）** | **7.5km** | **20秒** | **3/8** |
| 丘300m | 6.2km | 14秒 | 2/8 |

自動操縦は着地点の印を使わない。激突の数は「起伏が危険として効いている」証拠であって、面白さの証拠ではない。

# 翼竜滑空 — 遊べる縦切り

**面白さの仮説（1文）**

> 遠くの上昇気流を見つけて乗り継ぎ、落ちるはずだった場所より先へ行けたとき嬉しい。

灰色の箱。本番の翼竜モデル・植生・音楽は使っていない。この仮説だけを確かめる。

## 遊ぶ

**公開URL: https://yokobo103.github.io/yokobo-pterosaur-glide/**

手元で動かす場合:

```
npm install
npm run dev     # http://localhost:8141
```

- 操作は**左右だけ**。`←` `→`（`A` `D`）、スマホは画面の左半分／右半分を押しっぱなし
- 押している間だけ曲がる。速度は自動（傾けると勝手に減速する）
- 上がる空気の場所は**舞い上がる土ぼこりの柱**で分かる。数字も矢印も出さない
- ところどころに**越えられない高い山**がある。回り込む
- 翼竜は本物のモデル（RH02）、カメラは後ろ約5m。`?size=2|3` は比較用
- 木と岩はAstraの氾濫原の原型（遠くは代わりの形）。ところどころの高い山は火山。`?notrees` で木なし
- 強い上昇気流の中を**他の翼竜**が旋回している（回っている所には上がる空気がある）
- 恐竜は5種（すべてAstraのリグ版・実寸の3.5倍）。`?nodinos` で無し
  | 種 | 実寸→見せる大きさ | いる所 |
  |---|---|---|
  | ステゴサウルス | 7m→24.5m | 川の近くの開けた平地 |
  | ドリオサウルス | 3.2m→11m | 林の縁 |
  | トリケラトプス | 8m→28m | 乾いた開けた台地 |
  | ブラキオサウルス | 19.6m→69m(高さ42m) | 川沿いの低地。遠くからでも分かる |
  | アロサウルス | 8.3m→29m | 開けた所に1〜2頭 |
- 着地すると減速して翼を畳み、四足で降りる
- 既定は丘のある世界。`?world=flat` で起伏なし、`?world=ridge` で尾根の風の試作
- 右の帯と音が上昇率。芯に近いほど高く速く鳴る
- 日が傾くと空気は上がらなくなる。降りたところが記録
- `?seed=17` で同じ地形を再現。`R` またはダブルタップでやり直し

## なぜこの形になったか（測って決めた）

| 決めたこと | 根拠 |
|---|---|
| 制限時間を置かない | 20分の時計を置くと全戦略が3〜4kmに潰れた（差12%）。無制限だと2.97km→11.06km（3.7倍） |
| 代わりに日没で終わらせる | 無制限＋無限の場だと上手いほど落ちず、281km・7時間飛び続けて走行が終わらなかった |
| 操作は左右だけ | 速度操作を足しても上限は11.06kmのまま動かず、下限だけ3.53km→2.22kmに落ちた。難しさだけ増えて面白さは増えない |
| 上昇率を音で出す | 芯から80mずれると300m上がるのに16.6分（芯なら3.3分）、100mずれると上がれない。今どれだけ上がっているか分からないと左右の操作が運になる |
| 上昇気流の外は沈む | これが無いと素通りするだけで高度が増え、直進でも7.3km出てしまい「見送る」に代償が無くなった |

測定の詳細は `docs/FINDINGS.md`。

## 発見（Discovery）

飛びながら「あれは何だ」と思って近づくと発見になる。飛行は止まらず、控えめな知らせが出て、走行の終わりに今回の発見だけ並ぶ。

**発見できるものを足す方法**は `src/discoveries.js` の `DISCOVERIES` に1つ書くだけ。飛び方の計算には触れない。

```js
{
  id: 'astra_something',             // 重複しない名前
  name: '○○の群れ',                  // 画面に出る名称
  desc: '…',                         // 終わりの一覧に出る説明
  rarity: 'ときどき',                 // 希少度(表示だけ)
  radius: 320,                       // この距離まで近づくと発見
  spawn: { kind: 'cell', cell: 4200, chance: 0.6, salt: 31,
           pick: (ctx, x, y) => ctx.terrain.moisture(x, y) > 0.5 },   // 出現条件
           // 歩く恐竜なら { kind: 'herd', species: 'dryo' } にして、群れは world.js の SPECIES に書く
  cue:   { color: 0x6d5238, radius: 120, strength: 0.8 },  // 任意: 地面の色を変えて遠くから気づけるようにする
  model: { url: 'models/xxx.glb', scale: 3.5, draw: 2400,   // 任意: 動かないものの見た目(Astra製GLB)
           count: 5, spread: 55, impostor: 'cross' },       // 任意: 何頭を何m四方に散らすか / 遠景の板の作り方
}
```

- `spawn.kind` は `herd`(群れに付ける。`species` で種類を選ぶ) / `volcano` / `peak` / `cell`(条件に合う場所を探す) から選ぶ。
  新しい置き方(バイオーム別・完全ランダムなど)は `SPAWNERS` に足せば、種類側は1行で使える
- `model` を書かなければ、地形やすでにいるいきものをそのまま発見対象にできる(追加の描画は0)
- `model` を書くと、近くは本物・遠くは**モデルを撮った画像を貼った板**に自動で入れ替わる(90〜150mでぼかしながら交代)。
  GLBは `public/models/` に置き、テクスチャは `tools/glb-jpeg.py` で縮めてから使う
- `model.impostor: 'cross'` はいきもの用。遠景の板を1枚にして常にこちらへ向ける。
  既定(木用)は十字＋樹冠の水平板で、細い二足歩行に付けると2頭が重なったような形に見えた
- `model.count` / `spread` で、その場に何頭か散らせる。位置は場所から決まるので毎回同じ
- リグの無い静止モデルは `blender -b --factory-startup <元.blend> --python tools/export-static.py -- <出力.glb> <三角形の目標> [除外する名前]`
  で書き出す。頂点カラーの体色はそのまま残る

## 歩く恐竜を足す

1. **書き出し**: `tools/export-walker.py` の `SPECIES` に1つ足して書き出す（二足・四足の両方に対応）。
   Astraのリグには歩きが入っていないので、足のIK操作骨(`CTRL_Foot.*` / `CTRL_Fore|Hind.*.Foot`)を動かして
   Idle と Walk をここで作る。四足は 後左→前左→後右→前右 の順に位相をずらす(横歩き)。歩きは足踏み(前進はゲーム側)。
   接地している間に足が後ろへ動く速さ(スクリプトが出す `WALK_SPEED`)を控えておく。
   材質の色は頂点カラーへ焼き、部品は1つに結合する(群れにすると描画の回数がそのまま効く)
2. **世界**: `src/world.js` の `SPECIES` に1つ足す。`walk` は 1. の `WALK_SPEED`。
   `maxShown` で同時に描く頭数を抑える(1体=描画1回。部品のままだと1体18回になる)。
   `walk × timeScale × scale` がそのまま地面を進む速さになる(合っていないと足が滑る)。
   `pick` で置き場所の条件(高さ・傾き・林の濃さ・湿り気)を書く
3. **描画**: `src/scene.js` の View で `new Creatures(terrain, this.scene, SPECIES.<名前>)` を1行。
   モデルの読み込みは `src/main.js` で1行
4. **発見**: `src/discoveries.js` に `spawn: { kind: 'herd', species: '<名前>' }` で1つ足す
5. **検査**: `tools/check-walkers.mjs` の `KINDS` に1行足す（足の滑り・接地・向き・発見を測る）

## 構成

```
src/world.js    地形と上昇気流。ブラウザにもNodeにも依存しない純JS
src/flight.js   飛行と自動操縦。左右の入力(-1..1)だけを受ける
src/scene.js    three.js の描画
src/audio.js    上昇率の音
src/main.js     入力・ループ・検査用の口(window.__slice)
tools/tune.mjs   ブラウザなしで縮尺を詰める
tools/capture.mjs 実ブラウザで飛ばして絵と数字を取る／本物のタッチで指の検査
tools/sheet.mjs   撮った絵を1枚に並べる
```

**地形は運ばない。** 川の距離場・堤・段丘・種つきノイズの関数で、その場で作る。上昇気流もチャンク単位で必要になったときに湧く。だから場は無限で、転送量はゼロ。

### 地面の3層

| 層 | 大きさ / 升目 | 役目 |
|---|---|---|
| 近景 | 2.6km / 36m | 足元。木や恐竜と同じ細かさ |
| 遠景 | 13km / 144m | 見えている範囲のほとんど |
| 地平 | 34km / 500m | 霧に溶ける手前まで。**これが無いと6.5km先から水面の板が見えて、まっすぐな川のような線になる** |

- 3層とも**同じ中心**を使う(層ごとに丸めると、くり抜きと内側の四角がずれて、すき間から水面が見えた。実測で最大164mの帯)
- くり抜きは「1升 + 1段」ぶん内側まで。沈めた頂点に触れる四角形は形が崩れるので1升、作り直しが1コマ遅れてもすき間が空かないように1段
- 作り直しは重い(近景11ms・遠景18ms・地平8ms)ので**1コマに1層だけ**。遅れが1段を超えたら順番を待たない
- 重なった帯では粗い面が上に出ることがある。遠景→近景は最大2.8mで見えない(`tools/tmp-poke.mjs` で測った)
- 調査用: `?nowater=1`(水の板を消す) / `?debugground=1`(層ごとに色分け)、検査は `tools/check-ground.mjs`

### 地表の見え方（のっぺり対策）

地形そのものは**ゆるい**(傾きの中央値2.5° / 1km四方の高低差の中央値49m)。陰影を強めても形は読めるようにならなかった
(直射を2倍にしても明暗の幅は17→22どまり)。効いたのは次の2つ。

1. **色を地形の形に沿わせる**。`moisture` は川からの距離と独立したまだらだけだったので、`TUNE.moistHollow`(既定0.3)で
   「まわりより低い所=湿る／尾根=乾く」を足した。色の模様が起伏に沿うので、ゆるい地形でも形が読める。
   飛距離への影響は-2.6%(自動操縦8種の平均)。上昇気流も尾根寄りになり、見た目と物理が一致する
2. **世界座標に固定した手続き模様**(`SURFACE`)。画像を持たず、フラグメントで3段階の濃淡を出す。
   乾いて開けた所ほど砂色の斑が強い = 上昇気流が期待できる目印。細かい模様は距離で消してちらつきを防ぐ

明暗の幅(乾いた平地 高さ150m / 林の縁 高さ80m): **6→15 / 3→16**。1コマの時間は変わらず(実測差なし)。

## 縮尺（`src/world.js` の TUNE と `src/flight.js` の AIR）

| | 値 | 効く先 |
|---|---|---|
| 滑空比 | 13.0（沈下こみ10.8） | 1本の柱から次へ届く距離 |
| 上昇気流 | 間隔900m / 強さ5.5〜11.0 m/s / 半径110〜185m | 選択肢の数と、旋回の難しさ |
| 雲底 | 地面から150〜280m | 1本あたりの滞在時間 |
| 外の沈下 | 0.75 m/s | 見送ることの代償 |
| 日没 | 720秒 | 1走行の長さ |

`npm run tune` で、この縮尺での自動操縦の成績が出る。

## 検査

```
npm run build && node tools/run-checks.mjs   # 全部の検査を1回で(開発サーバー不要)
node tools/run-checks.mjs --public           # 公開版
npm run dev              # 別で起動しておく
node tools/capture.mjs --touch      # 手元
node tools/verify-public.mjs        # 公開URLが本当に飛べるか
```

- PC / スマホ の両サイズで、要所5場面の絵
- 実プレイ状態での描画コマ数
- **本物のタッチ**で左半分／右半分／左右同時の3件
